## KNX Security: проблема, о которой важно знать

KNX используется для автоматизации освещения, жалюзи, отопления, вентиляции, доступа и других инженерных систем зданий. Нарушение работы такой системы может затронуть не только комфорт пользователей, но и эксплуатацию всего объекта.

Одна из наиболее серьёзных проблем безопасности связана с механизмом **BCU Key** — ключом, ограничивающим доступ к программированию поддерживающих его устройств через ETS. Если неизвестный ключ установлен без ведома владельца, устройство может оказаться недоступным для штатного перепрограммирования.

В реальных инцидентах подобная блокировка приводила к тому, что владельцы теряли возможность восстановить оборудование обычными средствами ETS.

## 1. CVE-2023-4346: блокировка KNX-устройств через BCU Key

В 2023 году была опубликована уязвимость **CVE-2023-4346**, связанная с механизмом KNX Connection Authorization Option 1.

При наличии доступа к KNX-сети злоумышленник может получить возможность изменить конфигурацию некоторых устройств, не использующих дополнительные механизмы защиты, установить новый BCU Key и тем самым лишить владельца возможности штатного программирования.

В отдельных сценариях аналогичные действия возможны и при физическом доступе к устройству.

- **CVE:** CVE-2023-4346
- **CVSS 3.1:** 7.5 (High)
- **Возможное последствие:** потеря возможности штатного программирования устройства без корректного BCU Key.

### Масштаб проблемы

Исследование, представленное на Black Hat USA, показало, что поисковая система Shodan обнаруживала более 12 000 устройств BACnet/IP и около 130 устройств KNXnet/IP, доступных напрямую из Интернета. Это подчёркивает риски, связанные с открытым доступом к инженерной инфраструктуре.

## 2. Почему атакуют KNX-инсталляции

Мотивы подобных атак могут различаться. Без расследования конкретного инцидента установить их однозначно невозможно.

### Финансовая выгода

Нарушение работы инженерной инфраструктуры может использоваться как инструмент давления на владельца объекта или создания затрат на восстановление.

### Цифровой вандализм

Целью может быть вывод системы из рабочего состояния, повреждение конфигурации или демонстрация возможности вмешательства.

### Исследовательский интерес

Некоторые специалисты исследуют KNX ради изучения протокола, поиска уязвимостей или демонстрации новых методов атаки. Такие исследования могут способствовать обнаружению проблем безопасности и разработке мер защиты.

## 3. Какие способы восстановления существуют

Универсального способа восстановления всех KNX-устройств с неизвестным BCU Key не существует. Возможность восстановления зависит от аппаратной реализации устройства, механизмов защиты и доступных методов работы с памятью микроконтроллера.

### Восстановление через производителя

Некоторые производители могут предложить сервисную процедуру сброса или перепрограммирования устройства. Возможность такого восстановления необходимо уточнять для конкретной модели. Не во всех случаях этот вариант доступен.

### Проверка ключа через KNX-интерфейс — KNXunlocker

Существует открытый исследовательский инструмент **KNXunlocker**, предназначенный для проверки возможных значений BCU Key через KNX-интерфейс.

Эффективность этого метода зависит от реализации конкретного устройства, доступной информации о ключе и скорости проверки вариантов. Если часть ключа известна, количество возможных комбинаций может существенно сократиться.

### Анализ дампа памяти — KNX Memory Dump Analysis

Другой подход — чтение и анализ дампа памяти микроконтроллера (**KNX memory dump analysis**).

В опубликованных исследованиях продемонстрировано восстановление BCU Key на отдельных устройствах путём анализа дампов памяти. Возможность применения метода зависит от аппаратной платформы, расположения данных и состояния защиты чтения памяти (**Readout Protection, RDP**).

Важно различать оперативную память RAM и энергонезависимую память Flash/EEPROM. Наличие BCU Key в открытом виде в конкретной области памяти необходимо подтверждать для соответствующего устройства.
